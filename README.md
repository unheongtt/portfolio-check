# 持仓体检 PortfolioCheck — AI Native 组合风险诊断

> 个人投资者贴入持仓，1 分钟拿到一份「组合风险体检报告」——只提示风险，不荐股、不预测。
> 在线体验：https://portfolio-check-ajhq.onrender.com/

## 一、目标用户与非目标

**目标用户**：持有 A 股组合、在决策前想看清组合隐藏风险的个人投资者。他们的问题不是「缺数据」（同花顺/东财都有），而是「数字摆在那里，看不懂它意味着什么」。

**真实工作流**：贴入持仓（代码 + 权重）→ 拉行情/估值/财务/历史日线/行业概念归属 → 计算五类风险 → AI 把数字合成「为什么这是风险」→ 出体检报告。

**非目标（明确不做）**：不输出买卖建议、目标价、涨跌预测、收益承诺；不做账户级资产配置规划；不覆盖港股美股实时行情（估值/相关性维度需要 A 股数据源）。

**可衡量价值**：把「手动查 N 个标的 + 自己算集中度」的 2–4 小时压到 1 分钟；且每条结论可回溯到原始字段（来源/时点/单位/口径）。

## 二、核心设计

### 五类风险（全部确定性计算，可测试、可复现）

| 风险维度 | 检测口径（阈值见 `app/risk/engine.py`） | 数据依赖 |
|---|---|---|
| 集中度 concentration | 单标的权重 >30%；前三大 >70%；单一行业 >50% | 用户输入 + 种子行业归属 |
| 相关性 correlation | 两两日收益平均相关系数 >0.7 / >0.5 | 扶摇历史日线 |
| 估值 valuation | PE(TTM)>80 或 <0（亏损）；PB>10 | 扶摇估值快照 |
| 波动 volatility | 年化波动率 >40% / >25% | 扶摇历史日线 |
| 题材暴露 exposure | 同一概念 ≥3 只且权重 >40% | 用户输入 + 种子概念归属 |

### 数据状态显式化（合规底线）

每个数字都携带 `source / as_of / caliber / unit / data_status`。`data_status` 只有四种：`ok / stale / missing / error`。**非 ok 状态下数值一律为 None**（`test_compliance.py::test_failure_status_never_fake` 用断言写死），绝不静默生成「看起来正常」的数字。

### AI 角色（本产品相对「数据终端/搜索」的增量）

- **规则引擎（确定性）**：算出「集中度 33%」「PE 120x」这类硬指标；
- **LLM（可插拔，缺省降级规则模板）**：把多源异构数字合成「你组合的核心风险是 X，因为 Y」的自然语言解读，并区分 fact/inference/uncertain；
- **AI 永不生成数字**：所有数值只来自结构化数据源或确定性计算，AI 只做「读与讲」；
- **人机协作闭环**：每次 AI 产出落库 `ai_output`（模型/时间/输入引用/复核状态），未复核前 UI 恒显示「待复核」。

## 三、数据使用

| 数据源 | 用途 | 备注 |
|---|---|---|
| **扶摇**（同花顺金融数据 API） | 行情快照、估值（PE/PB/PS）、历史日线（相关性/波动率） | A 股；`X-api-key` 鉴权 |
| **iFinD MCP**（可选） | 港美股补充、宏观/新闻 | 当前主链路不强依赖 |
| **种子数据**（内置） | 示例组合 + 行业/概念归属（静态，标注来源） | 无凭证也能跑通集中度/题材暴露维度 |

行业/概念归属为静态元数据（同花顺口径），随 `seed_data/industry_concept.json` 分发，不是市场数字，故不涉及编造；市场数字只来自扶摇实时接口。

## 四、启动方式

```bash
# 1. 安装依赖（uv）
uv sync

# 2. 配置环境变量
cp .env.example .env   # 填入 FUYAO_API_KEY（必填，体验完整五维），IFIND/LLM 可选

# 3. 运行
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000
# 打开 http://localhost:8000
```

Docker 部署：`docker build -t portfolio-check . && docker run -p 8000:8000 --env-file .env portfolio-check`

## 五、测试

```bash
uv run pytest -q   # 30 个用例：风险引擎单元测试 + 主链路 + 合规边界
```

测试默认在**无凭证环境**下运行，专门验证「失败不兜底」：估值/相关性/波动显式报数据不足，集中度/题材暴露仍可计算。详见 `docs/测试说明.md`。

## 六、已知边界与未做事项

- **无凭证时估值/相关性/波动维度显式降级为「数据不足」**，不产出结论（这是有意设计，不是缺陷）；
- 相关性/波动率基于日收益计算，**未对齐交易日**（A 股近月交易日基本一致，误差可忽略；跨市场持仓时需注意）；
- 行业/概念归属为**静态种子**，未做逐日更新（行业分类低频变化，可接受）；
- **未做浏览器 E2E**（前端为静态 SPA，API 层已由 pytest 全覆盖）；
- 未接账户/持仓导入（当前为手动输入 + 示例组合），未做多账户/历史报告对比；
- 未配置 LLM Key 时解读为**规则模板**，表达不如 LLM 丰富，但语义等价且确定性可复现。

## 七、合规边界

全链路无「买入/卖出/目标价/涨跌预测/收益承诺」类输出；结论区分 fact/inference/uncertain；失败不兜底；AI 产出待复核；健康接口不泄露凭证字段；`.env` 与本地数据库已被 gitignore。以上均以测试固化（`tests/test_compliance.py`）。

## 目录结构

```
app/
  risk/engine.py        # 五类风险确定性计算（阈值集中，可测试）
  ai/analyzer.py        # LLM 解读合成 + 规则模板降级
  ai/rules.py           # 规则叙事模板（对照基线）
  datasources/          # 扶摇/iFinD 适配器 + 市场数据编排 + 本地缓存
  api/routes.py         # /api/check 主链路等
  models.py / db.py     # 领域模型 / SQLite 存储
static/                 # 前端 SPA（原生 JS，无构建）
seed_data/              # 示例组合 + 行业/概念归属
tests/                  # pytest（单元 + 主链路 + 合规）
```
