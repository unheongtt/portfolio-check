# AI 使用与验证记录

> 题目要求：说明使用了哪些 AI 工具、AI 参与哪些环节、候选人修正了哪些错误或不合理结果。

## 1. 使用的 AI 工具

| 工具 | 用途 | 参与环节 |
|---|---|---|
| **Claude Code（AI 编程助手）** | 代码生成、架构设计、文档撰写、测试编写 | 全项目：后端/风险引擎/前端/测试/README 均由 AI 辅助编写，关键逻辑人工审查 |
| **产品内置 AI 引擎（可插拔 LLM）** | 风险解读合成、整体摘要 | 运行时 `POST /api/check`；当前部署未配置 LLM Key，降级为规则模板 |
| **规则引擎（确定性降级）** | 五类风险计算 + 解读模板 | 无 LLM Key 时的全部解读；同时作为 LLM 输出的对照基线 |
| **Web 搜索（联网核验）** | 数据接口契约核验 | 扶摇历史日线接口（`/api/a-share/prices/historical` 的参数与字段）逐项核对官方契约 |

## 2. AI 参与的具体环节

1. **代码实现**：后端（FastAPI/风险引擎/适配层/AI 引擎）、前端 SPA、测试全部由 Claude Code 生成，人工逐块审查并修正（见第 4 节）。
2. **产品定义草拟**：五类风险维度、阈值口径、示例组合的初稿由 AI 起草。
3. **事实核验**：扶摇接口契约（历史 K 线端点、复权方式、毫秒时间戳）通过官方 `llms-full.txt` 核对；示例组合的行业/概念归属按同花顺公开口径核对。
4. **运行时解读**：产品内 AI 引擎对每条风险发现产出「为什么这是风险」的解读（待复核）。

## 3. 验证方法

- **接口契约核验**：扶摇历史日线端点（`/api/a-share/prices/historical`，单标的、`1d`、`adjust=forward`、毫秒时间戳）从官方契约原文核对后实现。
- **实时数据实测**：用扶摇真实 Key 跑通全链路——估值（中芯国际 PE≈118.9x、隆基绿能 PE 为负）、波动率（中芯国际年化≈58%）、相关性（两两 0.096–0.565，均值≈0.15）。实测结果回写本记录，作为「数字可回溯」的证据。
- **口径测试**：五类风险阈值以 `tests/test_risk_engine.py` 固化（如 Pearson=1 精确断言、diversified 组合不误报、概念扎堆 3 只且 >40%）。
- **不越权测试**：`test_failure_status_never_fake` 断言「非 ok 状态数值必为 None」，`test_no_buy_sell_advice` 断言无买卖/预测类输出，确保 AI 产出不越权。

## 4. 候选人修正的 AI 错误（抽样记录）

| # | AI 原始输出（错误） | 核验结果 | 修正 |
|---|---|---|---|
| 1 | 「数据不足」类发现里，`value` 填了 `0.0` 且 `data_status=missing` | 违反自身「非 ok 状态数值必为 None」的合规底线（测试断言抓到） | 改为 `value=None`，缺失原因放 `note`，固化进 `test_failure_status_never_fake` |
| 2 | 健康接口泄露测试把「未配置 iFinD MCP Token」文案里的英文单词 `token` 误判为密钥泄露 | 实际是「未配置」提示文案，非密钥值 | 改为断言健康接口只返回 name/configured/status/message，绝不回传密钥值 |
| 3 | 风险引擎引用 `KLINE_LOOKBACK_DAYS` 常量但未导入 | 常量定义在 datasources 层，engine 层不可见 | 改为内联口径字符串，避免跨层隐式依赖 |
| 4 | 相关性维度在「平均相关性低」时无任何输出，易被误读为「维度未生效」 | 实测两两相关性 0.096–0.565、均值≈0.15，确实是低相关（组合跨白酒/电池/光伏/半导体） | 保留「无风险不误报」的正确行为，并在 README/测试说明明确「未触发=低风险」口径 |
| 5 | 估值维度在无凭证时静默返回空（不产任何发现） | 与相关性/波动率「显式报数据不足」不一致 | 统一为显式「估值数据缺失」（uncertain + note），`test_valuation.py::test_insufficient_when_no_ok` 固化 |

## 5. 结论

- AI 在本项目中承担**加速器**角色（代码、初稿、结构化），所有**事实性结论（接口契约、阈值、行业归属）经过人工+联网双重核验**；
- 产品内 AI 的运行时角色被严格限制：**只解读、不生成数字、不荐股**——由测试固化；
- 规则引擎 + LLM 双轨设计保证无 Key 环境下的可复现性与有 Key 环境下的可扩展性。
